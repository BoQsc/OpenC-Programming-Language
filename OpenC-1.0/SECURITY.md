# OpenC security policy

## Supported release line

Security fixes are accepted for the current 1.0 release-candidate/release line.
Experimental Linux, freestanding, Native, script/live, and Concurrent sources
carry no 1.0 support claim unless a later release record explicitly adds one.

## Reporting

The OpenC project owner is the security contact and triage authority. Use the
private contact mechanism associated with the channel from which the release
was obtained. If that channel exposes no private mechanism, request a private
contact from the owner without including exploit details; do not place an
unpatched vulnerability or credential in a public report.

Reports should include the affected version, target, reproduction, impact, and
whether disclosure is time-sensitive. The owner will acknowledge, classify,
coordinate a fix and conformance regression where applicable, and publish an
advisory or erratum. No response-time warranty is offered.
